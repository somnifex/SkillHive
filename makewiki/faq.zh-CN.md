# 常见问题

## SkillHive 会直接执行 AI Skill 吗？

不会。SkillHive 用于保存、版本化、划分范围和治理 Skill 说明，不会代替用户运行 AI Agent，
也不会主动调用模型。

## 谁能读取我的私有 Skill？

普通应用 API 只有所有者可以读取。平台管理接口也不提供读取其他用户私有 Skill 正文的
能力。数据库和备份运维人员仍控制底层数据，因此部署方必须妥善保护。

## 使用群组模板会创建共享 Skill 吗？

不会。无论模板范围如何，实例化都会创建当前用户拥有的私有 Skill。群组范围决定谁能使用
模板，不改变生成结果的所有者。

## 模板和全局 Skill 有什么区别？

模板用来生成用户可以继续定制的新私有 Skill；全局 Skill 由平台统一维护版本与发布状态，
再由群组管理者按“最新”或“锁定”策略为成员启用。

## SQLite 可以用于生产环境吗？

SQLite 更适合单进程本机或小范围评估。共享部署通常更需要 PostgreSQL 的连接管理、外部
备份和运维监控。应按并发和恢复要求选择，而不是只看数据规模。

## 为什么系统里有示例用户？

因为启用了 Seed。它可重复执行且只用于开发。容器共享部署应设置 `SEED_DEMO=false`，并在
对外开放前删除或修改示例凭据。

## 目前还有哪些功能尚未实现？

- 忘记密码不会发送邮件，也不会重置凭据。
- 数据模型预留了邀请链接，但没有完整加入流程。
- 没有一键导出完整 Skill 包。
- 没有内置的多副本共享登录锁定状态。
- 仓库内部署不会自动提供域名、TLS、监控和托管备份。
